## 结论

**⚠️ 可用，无破坏性变更，但有 1 处真实可见的行为变化（菜单位置）+ 1 处视觉风险（顶栏裁切）。**

插件依赖的所有硬契约——写入路径 `binding.session.rename`、`ctx.llm.stream`、`ctx.sessionQuery.readSurface`、`ctx.webServer.register`、三个 slot id——在 0.2.2-rc.1 中全部原样保留。唯一会让人察觉的差异是「生成标题」在会话「…」菜单里的位置下沉了。

## 二、逐项核查

### 2.1 ⚠️ 会话菜单行位置变了（真实可见的回归）

`sidebar.workspaces.session.menu.item` 在 0.2.2 被明确降级为 **legacy 通道**。宿主源码说法（`packages/client/ui-workspace/src/client/contract/slots.ts`）：

> *"The Session menu adapter owns the legacy `sidebar.workspaces.session.menu.item` Slot for external React entries; they receive the captured row identity and **render together before Archive**."*

内置动作全部搬去了新的 `ctx.contextMenus`，`afterContent` 标记只留给 Archive：

| 菜单项 | 0.2.1 实现 | 0.2.2 实现 |
|---|---|---|
| pin | slot id `pin` order 100 | `ctx.contextMenus` order 100 |
| rename | slot id `rename` order 200 | `ctx.contextMenus` order 200 |
| fork | slot id `fork` order 300 | `ctx.contextMenus` order 300 |
| session-id | slot id `session-id` order 450 | `ctx.contextMenus` order 450 |
| **本插件「生成标题」** | **slot order 250 → 夹在 Rename 和 Fork 之间** | **legacy 块，排在 session-id 之后、Archive 之前** |
| archive | slot id `archive` order 400 | `ctx.contextMenus` order 600 + `afterContent` |

**功能不受损**：

- 组件 props 在 0.2.2 完全一致：`sessionId`、`displayTitle`、`useMenuOpenState`
- `hookContext` 仍通过 `menuOpenStateFactory` 绑定（`SessionMenu.tsx` 把 `[true, open => !open && dismiss()]` 作为 hookContext 传入）
- 点击后菜单照常关闭，弹窗照常弹出

**只是位置下沉**，`client.js:6` 的注释「a session-menu row under "Rename"」和 README 描述会变成错的。

**要保住「紧跟 Rename」的位置**，需迁移到新 API：

```js
ctx.contextMenus.register({
  id: 'session-titler.generate',
  target: 'session',
  order: 250,
  observe: ...,
  resolve: (target) => [{
    id: 'generate-title',
    label: t('action'),
    icon: { key: '...' },
    run: () => store.open({ sessionId: target.sessionId, currentTitle: target.displayTitle }),
  }],
})
```

参考实现：`packages/client/ui-workspace/src/client/session-actions/context-menus.tsx`。
代价：放弃 `useMenuOpenState` 的便利，改由 contextMenu 的 `target` / `dismiss` 控制开合。

### 2.2 ⚠️ 顶栏动作区现在会裁切溢出

`conversation.session.header.actions` 的 slot 文档新增：

> *"overflow is clipped and faded before the utilities, **so overlays must portal**"*

对应 CSS（`ConversationRoot.module.css` 的 `.titleCluster`）新增：

```css
overflow: clip;
mask-image: linear-gradient(to left, transparent calc(0.3 * var(--title-cluster-fade)), #000 var(--title-cluster-fade));
```

**为什么本插件不破**：按钮很小；确认弹窗挂在 `shell.overlay`（frame 级独立槽，不受该容器裁切）。
**残留风险**：窗口很窄、顶栏动作多时，按钮可能被渐隐掉一部分（视觉与命中区）。

0.2.2 还新增了 `job-list`(order 20)、`subagent-catalog`(10)、`agent-team` 三个占位者，都是正数 order；本插件的 `-8` 相对位置没变（仍在 agent-preset `-10` 之后）。

### 2.3 ✅ 写入路径完好（最脆弱处，但没变）

`ctx.sessions.using(id, {source:'workspaceOperation'}, ref => ref.binding.session.rename(title))` 在 0.2.2 逐字未变：

| 契约 | 状态 |
|---|---|
| `ISessions.using / retain / binding` 声明 | ✅ 完全一致 |
| `SessionBinding { sessionId, session, eventSource, ctx }` | ✅ 一致 |
| `ISession.rename(title): Promise<RemoteResult<{title, seq}>>` | ✅ 一致 |
| `SessionReferenceSource` 含 `'workspaceOperation'` | ✅ 仍在（ui-workspace 自己还在用） |
| 返回结构 `{ok:true} / {ok:false,error:{message}}` | ✅ 一致 |

所以「确认前不写入、确认后才写」的承诺继续成立。

### 2.6 🐛 既有潜在 bug（非 0.2.2 引入）

`title.js:502` 的兜底路径：

```js
const call = await llm.prepareCall({ provider, model, maxTokens, reasoningEffort }, options.signal)
```

而真实签名（两个版本都一样）是：

```ts
prepareCall(provider: string, model: string, signal?: AbortSignal): Promise<PreparedAdapterCall>
```

因为 `llm.stream` 一直存在，`typeof llm.stream === 'function'` 永远为真，这条分支**永不执行**，所以从未炸过。建议二选一：按真实签名修正，或直接删掉 `preparedTitleStream` 与 `unsupported-host` 那条提示。

```jsonc
// package.json
"dsh": ">=0.2.1-rc.5 <0.3.0-0",
```
